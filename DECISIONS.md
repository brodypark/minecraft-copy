# Decisions

The manager's decision log: choices made during the build, with the reason for each.

- **Project files live at the repository root**, not in a `voxel-game/` subfolder as drawn in PROJECT.md section 4. The repo is the project, so the extra folder adds nothing.
- **`blocks.js` ships a registry skeleton in Task 1.** Block flags (`solid`, `transparent`, `placeable`, `breakable`) are filled in now and `tiles` are placeholders that Task 2 assigns, so the parallel Group B tasks share one API (`BLOCKS`, `HOTBAR_BLOCKS`, `getBlockDef`, `isSolid`, `isTransparent`, `isPlaceable`, `isBreakable`) from the start.
- **Block flag helpers use flat `Uint8Array(256)` lookup tables** built once from `BLOCKS` at module load, so the mesher and physics hot loops do one array read per check. Unknown ids read as air (not solid, transparent, not placeable, not breakable). Consequence: `BLOCKS` flags must not be mutated at runtime; edit the source instead.
- **`main.js` uses `THREE.Timer`** for frame delta (clamped to 0.05 s), because `THREE.Clock` is deprecated in current three and logs a warning.
- **`alea` is a CommonJS/UMD package**; import it as a default export (`import alea from 'alea'`). This works in both Vite and vitest.
- **`build.chunkSizeWarningLimit: 1000`** in `vite.config.js`: three.js alone is ~525 kB minified, which would otherwise print a chunk-size warning on every build. Code-splitting three buys nothing for a single-page game.
- **Tile indices and `tileUV` live in a pure `src/render/tiles.js`** (re-exported from `atlas.js`). The mesher must not import three.js, and `atlas.js` needs three for `CanvasTexture`, so the UV math lives in a separate module with no dependencies. The texture keeps three's default `flipY = true`, so `v1` is the top edge of a tile.
- **Physics input convention:** `stepPlayer`'s `input.strafe` is the world-X component and `input.forward` the world-Z component of the desired horizontal direction. The caller (player.js) rotates WASD by yaw before calling. This matches "already rotated to world space" in section 5.6 while keeping the contract's field names.
- **The World records player edits itself** (`setBlock` writes to an edit map, `getEdits()` / `applyEdits()`). Edits are re-applied whenever a chunk is regenerated, so they survive chunk unload as well as save/reload. Save/load (Task 10) then needs no changes to `world.js`, which avoids a file conflict with Task 11.
- **World API additions beyond section 5.4:** `ensureChunk`, `generateAround` (synchronous spawn generation), `consumeUnloadedChunks` (so the renderer can dispose meshes), `pendingMeshCount` and `loadedChunkCount` (F3 overlay), and an optional `limit` argument on `consumeDirtyChunks` (edited chunks bypass it, per section 7 Streaming). Generation and render radii are circular (`dx² + dz² <= r²`). With `GEN_DISTANCE = RENDER_DISTANCE + 1` this still guarantees all 4 neighbors of every meshable chunk get data.
- **Atlas extras (Task 2):** `tileUVInto` (no-allocation variant for the mesher), `tileOrigin` (pixel origin, for hotbar icons) and `ATLAS_SIZE`. Each tile uses its own seeded stream `alea(seed, tileName)`, so changing one tile never shifts the others. Leaves and glass alpha is strictly 0 or 255, which works cleanly with `alphaTest: 0.5`.
- **Physics (Task 4):** physics tuning constants (water, acceleration, epsilons) moved into `config.js` so it really holds ALL constants; `physics.js` re-exports them. Vertical motion uses the trapezoid rule, so the jump apex (~1.26 blocks) doesn't depend on frame rate. Collision snaps leave a 1e-4 gap, and overlaps up to 0.01 are pushed back out. Landing while flying turns fly mode off (`state.flying` is written by physics, so the player code reads it back). Water: `inWater` is sampled at feet + 0.4, with 30% gravity, half horizontal speed, 3.5 b/s swim-up, and a shoreline boost when pushing into a 1-block lip while holding jump.
- **Constants policy:** tunable gameplay and world values (physics, terrain shape, tree chance) live in `config.js`. Purely algorithmic internals (hash salts, loop margins derived from the tree shape) stay next to their code.
- **Terrain (Task 3):** the height constants in section 6 (2, 14, 10) only reach about y 35 because fbm is normalized to [-1, 1]. Tuned to BASE 3, DETAIL 18, HILL 40: the highest point of each 256x256 area is about y 46, roughly 20% of columns are under water, and neighboring columns never differ by more than 3 (measured over 2048² blocks, 3 seeds). The tree hash is integer-only MurmurHash3 (an earlier xor hash collided for mirrored coordinates). Generating 13x13 chunks takes about 17 ms in node.
- **World details (Task 3):** a corner edit also dirties the diagonal neighbor chunk, which ambient occlusion needs. `setBlock` rejects non-integer coordinates and unknown ids, and a same-id set is a no-op. Unloading runs only when the player crosses into a new chunk. Spawn uses `terrain.surfaceHeight` (not `heightAt`, which counts leaves) to find land.
- **Mesher (Task 5):** positions are chunk-local and each mesh sits at (cx·16, 0, cz·16), which keeps float precision and gives per-chunk bounding spheres. The mesher copies the chunk plus a 1-block border into a padded array once (18×64×18 `getBlock` calls) and meshes from that. Measured 0.15–0.35 ms per chunk (about 3.8k vertices and 1.9k triangles), so a Web Worker isn't needed. `chunkMeshes` converts baked vertex shades from sRGB to linear on upload, because three treats vertex colors as linear; otherwise face shading looks flat on screen. Material brightness is set in sRGB for the same reason. Top and bottom faces use north (-Z) as texture "up".
- **Controls and player (Task 6):** `findSpawn` also rejects columns with a tree root within 2 blocks, so the player never spawns on a canopy. Mouse-wheel events are throttled to one step per 50 ms in the same direction, so trackpads don't skip slots. Double-tap detection uses `e.timeStamp` and ignores auto-repeat. `teleport` zeroes velocity and `respawn` also ends flight. The seed comes from `?seed=<int>` or is random until save/load supplies it. The renderer's fog and camera constants moved into `config.js`.
- **Dev-only automation hook:** `window.__game` (with `setForcePlay`) exists only under `import.meta.env.DEV` and is stripped from production builds. The manager uses it to drive the game from headless Chrome (pointer lock isn't available headless). Headless checks run in Chrome with SwiftShader. SwiftShader logs "GPU stall due to ReadPixels" warnings whenever a screenshot is taken; those come from the test harness, not the game.
- **Raycast and editing (Task 7):** a ray starting exactly on a block face returns that block with the face normal at distance 0; normal (0,0,0) is reserved for an origin strictly inside a block, and placement refuses it. Break and place re-read the world instead of trusting `hit.id`. Place also refuses when the block it would sit against is gone, so a stale hit can't create a floating block. Placing into water replaces the water. The target outline factory lives in a separate `src/render/outline.js`, which keeps `interaction.js` free of three.js and unit-testable.
- **HUD (Task 8):** "New World" asks for confirmation inline (no browser `confirm()` dialog, which would block automation and look out of place). Hotbar icons are drawn at 64 px and shown at 32 CSS px. Their alpha is snapped to 0 or 255 after drawing, because canvas anti-aliases transformed images and leaves seams between faces. Transparent blocks (glass, leaves) also draw their back faces. Presentational UI constants (animation timings, icon shading) stay in the UI modules; the constants policy covers gameplay, world and render tuning.
- **Sky (Task 9):** time of day runs over [0, 1) with 0 = midnight, 0.25 = sunrise, 0.5 = noon, 0.75 = sunset, and the game starts at 0.3. Brightness is 1.0 from about 0.33 to 0.67, 0.25 from about 0.80 to 0.20, and about 0.5 at sunrise and sunset. The sun's orbit leans 0.35 rad toward +Z, rising at +X (east) and setting at -X. Stars fade in at night. Underwater fog (0.5–14 blocks, blue-green) is multiplied by brightness so water is dark at night. Time stops while the game is paused. The signature is `createSky(scene)`, since the renderer isn't needed.
- **Group E wiring:** frame order is dt → player → hotbar/F3 → target + edits → streaming → unload → mesh budget → sky → debug stats → render. Edits happen before the mesh step, so edited chunks (which skip the per-frame limit) remesh in the same frame. Until save/load landed, "New World" reloaded with a fresh random `?seed=`.
- **Save/load (Task 10):** one localStorage key (`voxel-sandbox-save`, version 1). `parseSave` never throws: a wrong version or a seed that isn't a safe integer means no save; bad edit entries are dropped one by one; an unusable position keeps the edits and starts the player at spawn; pitch is clamped to ±89°. `createAutosaver` saves every 10 s and on `beforeunload`, and `stop()` removes both, so "New World" (stop → clear → reload with a new `?seed=`) never re-saves the old world while unloading. **`?seed=` vs a save:** a URL seed that differs from the saved seed starts a fresh world, which overwrites the save at the next autosave; a matching seed restores the save, so reloading after "New World" keeps progress. Edits are applied to the World before any chunk generates.
- **Polish (Task 11):** baked AO uses the classic 3-neighbor rule; only opaque blocks occlude, and water gets no AO. Factors are [0.5, 0.65, 0.82, 1.0] for levels 0–3, stored as sRGB like the face shades. The quad diagonal flips on `l0+l2 > l1+l3`, which removes the anisotropy artifact. A diagonal neighbor chunk that isn't loaded reads as air for AO. Idle frames allocate nothing: `consumeDirtyChunks` and `consumeUnloadedChunks` return reused arrays (valid until the next call), a version counter skips the dirty scan when nothing changed, and `chunkMeshes` swaps geometries on persistent meshes. Caves come from 3D simplex (`noise3D(x/28, y/14, z/28) > 0.62`, tapered near the limits), only for 5 ≤ y ≤ min(own and 4 neighbor surfaces) − 5. Caves therefore never reach the surface or touch water, and players find them by digging. They add about 33% triangles to the spawn area (212k → 282k), and 13x13 generation now takes 56 ms.
- **Meshing cost and memory (Task 11, measured):** meshing with AO and caves takes 0.35–0.37 ms per chunk on average and 0.6–0.7 ms at most in node, and uploading the geometry takes 0.085 ms on average (0.6 ms max) in headless Chrome. That is far below the 6 ms threshold, so no Web Worker is used and `CHUNK_MESH_PER_FRAME` stays at 2. Memory: a headless 85 s flight covered about 1,440 blocks (783 chunk meshes built and disposed). `renderer.info.memory.geometries` went 79 → peak 223 → settled at 135–215, never trending up. Loaded chunks plateaued at 191 and meshes at 162, the JS heap stayed between 49 and 59 MB, and textures stayed at 1. Geometry disposal is working.
